# 架构设计

## 1. 设计目标

本项目的设计目标是把 OCR 审核能力服务化，并同时满足以下要求：

- 兼容同步调用模式，降低接入成本。
- 支持 GitLab Webhook 异步模式，减少等待时间。
- 对审核结果进行持久化，支持重启恢复。
- 在 GitLab 回写失败时不影响审核主流程。
- 支持规则中心化配置，便于统一维护。

## 2. 总体架构

服务由四条主链路组成：

- API 层：接收健康检查、同步审核和 webhook 请求。
- 审核层：调用 `ocr review`，解析结果并做策略判定。
- 持久化层：使用 SQLite 保存任务、状态和 webhook 事件。
- 集成层：封装 GitLab API 和飞书规则同步。

## 3. 模块职责

### `app/main.py`

负责 FastAPI 入口、路由定义、线程池并发控制、Webhook 入队和任务恢复。

### `app/reviewer.py`

负责构造 `ocr` 子进程环境、执行审核、解析 JSON、判断通过与否、生成摘要和评论。

### `app/repo_cache.py`

负责 bare repo 缓存与 worktree 管理，减少重复 clone 成本。

### `app/gitlab_client.py`

负责 GitLab 仓库地址转换、MR 详情获取、inline 评论、汇总 note 和讨论状态更新。

### `app/storage.py`

负责 SQLite 表初始化、任务创建、状态更新、任务查询和 webhook 事件记录。

### `app/trigger_check.py`

负责判断某个 MR 是否需要触发审核。

### `app/rule_updater.py`

负责从飞书电子表格读取自定义规则并写入 ocr 配置。

## 4. 数据设计

### `review_task`

保存异步审核任务的核心状态。

关键字段：

- `task_id`
- `project_id`
- `mr_iid`
- `source_branch`
- `target_branch`
- `commit_sha`
- `status`
- `approve`
- `summary`
- `stats_json`
- `error`
- `gitlab_posted`

### `webhook_event`

保存 webhook 事件日志，便于排障和审计。

## 5. 关键流程设计

### 审核执行

1. 统一从配置中注入 LLM 和 GitLab 信息。
2. 通过 repo cache 获取稳定的 worktree。
3. 每次审核前同步规则配置。
4. 执行 `ocr review`。
5. 使用 severity 规则计算 approve/reject。
6. 需要时回写 GitLab。

### 任务恢复

服务启动时会读取 `queued/running` 任务并重新投递，避免服务重启后任务丢失。

### 回写补偿

后台轮询未回写成功的终态任务，对 GitLab 进行补发，降低偶发网络错误带来的结果丢失。

## 6. 并发与稳定性

- 使用 `ThreadPoolExecutor` 限制同一时间的审核数量。
- GitLab API 调用带重试和退避。
- `ocr` 子进程执行有独立超时。
- GitLab 回写失败不会影响最终 approve 判定。

## 7. 配置策略

设计上遵循“运行时注入，配置驱动”的原则：

- 敏感信息通过环境变量注入。
- 审核阈值通过 `BLOCKING_SEVERITIES` 控制。
- 触发策略通过分支规则和标题前缀控制。
- 飞书规则更新是可选能力，不应阻断主流程。

## 8. 后续扩展点

- 引入更清晰的任务队列抽象。
- 增强审核结果索引和检索能力。
- 支持多租户或多 GitLab 实例隔离。
- 将文档与配置校验做成启动检查。

## 9. 页面展现与审核记录管理

本章节用于承载面向运营和排障的页面能力，后续迭代优先对齐这里的设计目标。

### 9.1 设计目标

- 提供一个可视化页面，展示审核任务、状态、结果和回写情况。
- 支持按项目、MR、状态、时间、分支等维度查询审核记录。
- 支持查看单次审核的详情，包括评论、warning、统计信息和错误原因。
- 支持对历史审核记录进行筛选、排序和追踪。

### 9.2 数据来源

- 任务主表 `review_task` 作为页面列表的基础数据源。
- `webhook_event` 作为请求追踪和排障辅助数据源。
- 审核结果中的 summary、comments、warnings、stats 作为详情页内容。

### 9.3 页面能力边界

- 列表页展示任务概览和状态分布。
- 详情页展示单次审核的完整上下文。
- 管理页支持回看失败任务和回写失败任务。
- 页面仅负责展示和管理，不直接改变审核决策逻辑。

### 9.4 后续扩展方向

- 增加任务搜索与过滤条件。
- 增加审核记录归档和导出能力。
- 增加按项目维度的统计看板。
- 增加失败任务的重试入口与操作审计。

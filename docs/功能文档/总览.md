# 功能总览

## 1. 项目目标

OCR Server 是一个基于 FastAPI 的代码审核服务，封装 Alibaba OpenCodeReview（ocr）CLI，对 GitLab Merge Request 进行自动化审核，并将结果回写到 GitLab。

## 2. 核心能力

- 接收同步审核请求，返回审核是否通过、摘要、评论和统计信息。
- 接收 GitLab Merge Request Webhook，异步触发审核。
- 调用 `ocr review` 分析 MR diff，产出问题列表和建议。
- 根据 severity 策略决定是否阻止合并。
- 将 inline 评论和汇总 note 回写到 GitLab。
- 将任务状态持久化到 SQLite，支持重启恢复和补发。
- 在每次审核前同步飞书电子表格中的自定义规则。

## 3. 对外接口

### `GET /health`

健康检查接口，返回服务状态、ocr 可执行文件名和 LLM 地址。

### `POST /review`

同步审核接口，适合兼容现有调用方。

请求字段：

- `project_id`
- `project_url`
- `source_branch`
- `target_branch`
- `mr_iid`
- `commit_sha`（可选）

返回字段：

- `approve`
- `summary`
- `reject_reason`
- `status`
- `stats`
- `comments`
- `warnings`
- `session_id`

### `POST /gitlab/codeReview`

GitLab Merge Request Webhook 接口，异步触发审核。

### `GET /status/{task_id}`

查询异步任务状态、审核结果和 GitLab 回写状态。

## 4. 业务流程

### 同步审核流程

1. 接收 `/review` 请求。
2. 转换仓库地址为可 clone 的 GitLab URL。
3. 准备 bare repo 和 worktree。
4. 同步飞书审核规则到 ocr 配置。
5. 调用 `ocr review` 执行审核。
6. 解析结果并计算是否通过。
7. 需要时回写 GitLab inline 评论和汇总 note。
8. 返回审核结果。

### Webhook 异步流程

1. GitLab 发送 Merge Request webhook。
2. 校验 `X-Gitlab-Token` 和事件类型。
3. 判断目标分支和标题是否需要触发审核。
4. 创建任务并入队。
5. 后台执行审核。
6. 回写 GitLab，更新任务状态。
7. 通过 `GET /status/{task_id}` 查询结果。

## 5. 配置项

主要通过环境变量配置：

- `OCR_LLM_URL`
- `OCR_LLM_TOKEN`
- `OCR_LLM_MODEL`
- `GITLAB_URL`
- `GITLAB_TOKEN`
- `WEBHOOK_SECRET`
- `MAX_CONCURRENT_REVIEWS`
- `OCR_CONCURRENCY`
- `BLOCKING_SEVERITIES`
- `FEISHU_ENABLED`
- `FEISHU_SPREADSHEET_TOKEN`

## 6. 结果判定规则

- 默认将 `critical` 和 `high` 视为阻断级问题。
- 只要命中阻断级问题，`approve=false`。
- 无阻断级问题时，`approve=true`。
- `ocr` 返回异常状态时，默认不放行，避免假绿。

## 7. 外部依赖

- GitLab API
- OpenCodeReview CLI
- LLM 兼容接口
- 飞书电子表格 API（可选）

## 8. 已知约束

- 单次审核耗时通常为数分钟。
- 审核过程会消耗大量 token。
- GitLab 项目需要启用 Pipelines must succeed 才能形成阻断效果。
- `ocr` 自动更新需要关闭，避免版本异常。

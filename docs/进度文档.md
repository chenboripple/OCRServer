# 进度文档

## 管理原则

本进度文档以设计文档为唯一管理基准。后续由 agent 迭代时，应优先读取设计文档中的模块职责、关键流程、数据设计和扩展点，再据此更新进度。

## 设计驱动的迭代方式

- 每一项进度都应对应到设计文档中的一个或多个小节。
- 进度更新时，优先描述“设计项是否已实现、是否验证、是否需要补充”。
- 新增任务前，先在设计文档中找到承载它的章节；如果没有对应章节，先补设计再排进度。
- 进度文档只记录当前执行状态，不承担重新定义方案的职责。

## 进度更新规则

| 规则 | 要求 |
|---|---|
| 设计先行 | 任何实现变更都要回写到对应设计章节下的进度状态。 |
| 双向校验 | 任何设计变更都要同步检查进度文档是否需要改写。 |
| 表格管理 | 进度文档按表格维护，不按时间线堆记录。 |
| 一行一项 | 每个设计章节至少对应一行进度，便于 agent 后续逐项更新。 |
